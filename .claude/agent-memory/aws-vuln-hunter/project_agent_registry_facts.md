## CONFIRMED FINDING (F-1) — route aws-security
AWS-managed policy `arn:aws:iam::aws:policy/AgentRegistryFullAccess` **v2** contains statement `AgentRegistrySecretsManagerAccess`: `Allow secretsmanager:GetSecretValue` on `arn:aws:secretsmanager:*:*:secret:*` **with NO Condition** (every KMS statement beside it IS gated by `kms:ViaService=agent-registry.*`/`aws:CalledVia`). Proven: a role holding ONLY this policy read a canary secret directly (get_secret_value 200, no agent-registry call path). => registry-admin grant = full secrets read. **Re-verified 2026-09-07 (independent fresh run, acct 183174222929):** v2 still DefaultVersion; simulate-custom-policy=allowed/no-MissingContextValues; scoped role (exactly 1 attached policy, 0 inline) get_secret_value on unrelated canary=HTTP200, byteLen match, VersionId+RequestId f7c09ad9-c374-40e6-9dcb-bebddc4016fc; nonexistent secret=ResourceNotFoundException (authz PASSED, so no SCP/RCP/PB hard-stop); gated-variant simulate=implicitDeny(Missing aws:CalledVia) w/o ctx & allowed w/ ctx => the missing condition is genuinely the cause. VERDICT CONFIRMED. Torn down (role NoSuchEntity, secret force-deleted). Same policy also over-broad (same-account, medium): `GetResourceOauth2Token`/`GetWorkloadAccessToken`/`ListOauth2CredentialProviders` on `*` providers, `iam:ListRoles` on role/*. Remediation: add `aws:CalledVia=agent-registry.amazonaws.com` guard.

## Controls that HELD (all refuted/blocked)
- **SSRF `fromUrl`:** create-time layered validation — `https://`-only regex; IP literals (incl 169.254.169.254 & private) rejected "must use a hostname, not an IP address"; `localhost` "fromUrl is invalid"; URL validation precedes registry-state check. Prior same-day: resolved-IP egress filter blocks non-public IPs incl after redirect; `http://` rejected at runtime; JWT discovery fetcher no redirects. Fleet UA Apache-HttpClient/Java. NO hard-stop.
- **Confused deputy (IAM):** cross-account roleArn => 403 "a cross-account role cannot be used with the iam:PassRole action". PassRole gated by `iam:PassedToService=agent-registry` (simulate: implicitDeny w/o ctx). Same-account signing primitive runs (CREATE_FAILED on unresolvable host) but SigV4 host-bound, no key exfil.
- **Confused deputy (OAuth twin):** `oauthCredentialProvider.providerArn` cross-account ARN accepted at create but token mint resolves in CALLER's account — a provider that EXISTS in acct B returns "does not exist" when referenced from A. No cross-account token mint. (Tested with real GithubOauth2 provider created in B.)
- **Provenance spoof:** `provenance` field ABSENT from 2025-12-01 model (Create AND Update) => ParamValidationError; not in Get output. Reserved-field guarantee enforced structurally.
- **Approval:** APPROVE_ALL auto-approves on Submit (record DRAFT at create). Owner can self-approve own registry (Submit vs UpdateStatus are separable IAM actions => maker/checker is customer-enforceable, not a bug). Cross-registry approval blocked: wrong registryId=>404, ARN/path mismatch=>400 "Registry ID mismatch between path and record ARN".
- **Cross-tenant (B->A):** short-id=>404 ResourceNotFound (per-acct namespace, no leak); full-ARN=>403 "no resource-based policy allows". Both control & data plane. No authorizerType still IAM-gated (fail-open refuted). `filters` are enum/field-validated (List: [descriptorType,recordType]; Search: [recordType,name,recordVersion]); `$`-operator DSL does NOT exist => filter injection refuted.
- **Area 6 org auto-detection:** NO AutoDetection/Organization/Encryption shapes in deployed control-plane model (CreateRegistry has only discoveryConfiguration+approvalConfiguration). Backend exists (SLR references orgs-read + Config) but no customer API => BLOCKED. SLR `AWSAgentRegistryServiceRolePolicy` v2 orgs access is READ-ONLY, record RW gated `aws:ResourceAccount=${aws:PrincipalAccount}` => not over-privileged.
- **Area 8 injection sink:** `description`/`custom.data`/`displayName` stored & returned VERBATIM by control get + data-plane BatchGet, but same-account IAM-bounded => informational (consumer-trust dependent, not AWS defect).
