**VL1 (cross-account listener-rule tamper) = REFUTED.** IAM identity side is over-broad: `SimulateCustomPolicy` with the Lattice v2 doc → `UpdateRule`/`GetRule`/`UpdateListener` on a FOREIGN-acct (B) rule ARN all `allowed` (wildcard account, no cond). BUT the LIVE cross-account call fails: stood up service+listener+rule in B, RAM-shared service to A (allowExternalPrincipals=True, A accepted invite), assumed a scoped role in A holding ONLY the Lattice policy → `UpdateRule`/`GetRule` on B's rule ARN → **AccessDeniedException** ("is not authorized to perform: vpc-lattice:UpdateRule on resource arn:...:289531347876:..."). Even A's FULL-ADMIN (research-admin, vpc-lattice:*) → same AccessDenied. B's rule match stayed `/canary-ORIGINAL-B` (NO tamper). ⇒ The VPC Lattice SERVICE PLANE enforces cross-account authz independently: RAM-sharing a service conveys CONSUMPTION (service-network assoc), NOT rule read/mutation. Owner must grant via an auth policy. Defense-in-depth holds; the managed-policy wildcard-account ARN is a LATENT over-broad identity grant, harmless cross-account. **Technique: IAM-sim `allowed` on a foreign ARN is NOT a cross-account breach — always confirm with a live assumed-role call; the resource-side/service plane is the real gate.**

**ADJ-ALB1 (same-account WAF strip) = CONFIRMED hardening-defect (IAM-sim; Tier-2, route aws-security).** `SimulateCustomPolicy` with the ALB v1 doc → `elasticloadbalancing:SetWebACL` and `DeleteWebACLAssociation` on any same-acct `loadbalancer/app/*/*` = `allowed`, no AmazonECSManaged tag gate. (The `wafv2:DisassociateWebACL` sim returns implicitDeny regardless of ARN shape — a simulate resource-type-match quirk, not the operative path; the ELB SetWebACL/DeleteWebACLAssociation path IS the detach and it's ungated.) Same-account needs only identity-allow (no resource-side cross-check) ⇒ a holder of this uneditable AWS-managed policy can strip the WebACL off ANY same-account ALB incl. non-ECS-managed ones. AWS-authored artifact, uneditable by customer. Same shape as the Lattice wildcard: broad on paper, but same-account there's no second gate so this one bites.
