Verdicts from run 2026-10-16-1 against accounts A/183174222929 + B/289531347876. Zero hard-stop hits.

**Why:** avoids re-litigating refuted docs-diff leads; preserves the two confirmed managed-policy findings so they aren't re-derived.

**How to apply:** treat refuted items as closed unless a doc/env change reopens them; the two managed-policy weak defaults are confirmed findings (AWS-managed, customer can't edit).

- **network-security-manager admin plane is org-gated server-side.** `PutAdminAccount`/`DeleteAdminAccount`/`ListAdminAccounts` all fail `403 AccessDeniedException "not authorized to perform organizations:DescribeOrganization"` even under AdministratorAccess (which includes organizations:*). Neither in-scope account is in an AWS Organization, so the whole NSM delegated-admin cluster (H1 takeover, H2 teardown, H3 scope bypass, H4 cross-org SLR, H5 visibility) is REFUTED/BLOCKED here: the "management-account only" gate is NOT prose-only, it's enforced by an internal Organizations lookup. Account-local `ListScopes` returns 200/empty. `SimulatePrincipalPolicy` says allowed (admin matches `*`) — not an existence oracle.
- **securityhub V2 id/UID resolution is account-scoped.** `GetExportJobV2` with another account's opaque jobId → `404 Export not found` (owner reads it fine). `GetRemediationsV2`/`ListExposuresByRemediationV2` return `404 Remediation target not found` for a foreign-ARN TargetUid (can't synthesize a real one — service-generated). HubV2 is not subscribed by default; `EnableSecurityHubV2`/`DisableSecurityHubV2` toggles cleanly. Export jobs need a dest S3 bucket + CMK whose policies grant `exportv2.securityhub.amazonaws.com`.
- **lakeformation RLS-policy IDOR is unreachable.** `AttachRLSPolicy`/`DetachRLSPolicy`/`UpdateRLSPolicy`/`CreateRLSPolicy` exist in the IAM authorization reference but have NO public botocore API op (61 ops, zero RLS-named). The real RLS mechanism is DataCellsFilter, which is account-isolated: cross-account `TableCatalogId` → `AccessDenied` (merged not-found/not-authorized, no existence oracle); own-account → `EntityNotFound`.
- **securityagent integrations are account-scoped and not agentspace-bound.** `CreateIntegration` (GITLAB) defers token validation and mints an opaque `i-...` id with no agentSpaceId param. Foreign account reading that id → `404 Integration not found` (cross-account refuted). `GetIntegration` never returns the webhook `secret`; `UpdateIntegration` vends it but ONLY for Bitbucket Data Center (`webhookAction only supported for Bitbucket Data Center`), which needs an OAuth code/state that is unreachable.
- **Cognito:** `email_verified` is non-mutable via `SignUp` (`InvalidParameterException` — platform-protected, refuted). But custom attributes (`custom:role`, `custom:tenant`) DO persist verbatim from an unauthenticated SignUp (default-permissive client WriteAttributes — customer-config footgun, not a platform bypass). `DescribeUserPoolClient` is access-level Read yet returns the 52-char `ClientSecret`; confirmed under a role holding ONLY `cognito-idp:DescribeUserPoolClient` (documented behavior / privilege seam, no cross-tenant crossing).
