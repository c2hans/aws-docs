Both flagship 2026-09-25 services are LIVE but have NO botocore SDK client (botocore 1.43.95). Reach them with hand-crafted SigV4 (helper pattern: sign an `AWSRequest` with `botocore.auth.SigV4Auth`, send raw bytes via urllib3). See [[aws-env-setup]].

**Network Security Manager (REST-JSON):**
- Endpoint host: `network-security-manager.us-east-1.api.aws` (NOT `*.amazonaws.com` — that's only the service principal). SigV4 signing name = `network-security-manager` (hyphenated); `networksecuritymanager` is rejected with InvalidSignature "should be scoped to correct service".
- Paths from API docs: `GET /admin-accounts`, `GET /admin-account/{acct}`, `PUT /admin-account`, `GET /policies/{urlencoded-ARN}`, `GET /scopes/{arn}`, `GET /deployments/{arn}`, `GET /resource-sync-statuses?deploymentIdentifier=<ARN>`.
- Onboarding gate: an account with no NSM resources returns HTTP 400 ValidationException `ACCOUNT_NOT_ONBOARDED` on list/admin ops.
- `Get*` with a bare id → 400 "must be the resource's ARN". Foreign-account ARN → **403 AccessDenied"no resource-based policy allows"** (standard IAM cross-account, fires PRE-existence). Same-account nonexistent ARN → 404. List ops that take an identifier as a QUERY param (ListResourceSynchronizationStatuses) still resolve it to the resource ARN and enforce cross-account 403. So cross-account IDOR + enumeration oracle are REFUTED.
- `PutAdminAccount` from a standalone (non-org) account returns **500 InternalServerException** (NOT 403) — likely org-lookup/SLR failure. Definitive org-takeover oracle needs the caller to be a NON-management member of a real Organization; NOT testable with standalone in-scope accounts.

**CloudWatch Omni (Smithy RPC v2 CBOR):**
- Endpoint host: `cloudwatch-omni.us-east-1.api.aws`. SigV4 signing name = `cloudwatch`. Wire = CBOR (`cbor2` is installed).
- Protocol path: `POST /service/{ServiceShape}/operation/{Op}` with headers `smithy-protocol: rpc-v2-cbor`, `Content-Type: application/cbor`. **The Smithy service-shape name is `CloudWatchOmniFrontend`** (found by unsigned sweep: right shape → coral `MissingAuthenticationTokenException`; wrong → `UnknownOperationException`). Root `/` + X-Amz-Target is NOT used.
- Body is a CBOR map of the JSON input members (member key casing exactly as docs).
- **Authz asymmetry (important):** org/credential ops (`GetSpaceCredentialsForOrganization`, `CreateDomainAccessGrantForOrganization`, `ListSpacesForOrganization`) do **authz-first → 403 AccessDeniedException** even for a fabricated spaceId/domainId (gate fires before resource resolution → cross-account cred-theft & domain self-grant REFUTED). But `SearchPrincipals` and `CreateOneTimeDeepLinkCode` do **existence-first → 404 ResourceNotFoundException "Domain not found"** for a nonexistent domain — a possible pre-authz domain-existence enumeration oracle (domainIds are low-entropy `d-[0-9a-z]{1,25}`). Could NOT confirm the "existing foreign domain" half without creating a real domain (blocked: domain creation entangles the org IdC instance owned by out-of-scope acct 532876697804).
