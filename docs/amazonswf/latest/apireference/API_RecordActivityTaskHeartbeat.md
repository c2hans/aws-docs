# RecordActivityTaskHeartbeat
<a name="API_RecordActivityTaskHeartbeat"></a>

Used by activity workers to report to the service that the [ActivityTask](API_ActivityTask.md) represented by the specified `taskToken` is still making progress. The worker can also specify details of the progress, for example percent complete, using the `details` parameter. This action can also be used by the worker as a mechanism to check if cancellation is being requested for the activity task. If a cancellation is being attempted for the specified task, then the boolean `cancelRequested` flag returned by the service is set to `true`.

This action resets the `taskHeartbeatTimeout` clock. The `taskHeartbeatTimeout` is specified in [RegisterActivityType](API_RegisterActivityType.md).

This action doesn't in itself create an event in the workflow execution history. However, if the task times out, the workflow execution history contains a `ActivityTaskTimedOut` event that contains the information from the last heartbeat generated by the activity worker.

**Note**
The `taskStartToCloseTimeout` of an activity type is the maximum duration of an activity task, regardless of the number of [RecordActivityTaskHeartbeat](#API_RecordActivityTaskHeartbeat) requests received. The `taskStartToCloseTimeout` is also specified in [RegisterActivityType](API_RegisterActivityType.md).

**Note**
This operation is only useful for long-lived activities to report liveliness of the task and to determine if a cancellation is being attempted.

**Important**
If the `cancelRequested` flag returns `true`, a cancellation is being attempted. If the worker can cancel the activity, it should respond with [RespondActivityTaskCanceled](API_RespondActivityTaskCanceled.md). Otherwise, it should ignore the cancellation request.

## Request Syntax
<a name="API_RecordActivityTaskHeartbeat_RequestSyntax"></a>

```
{
   "details": "{{string}}",
   "taskToken": "{{string}}"
}
```

## Request Parameters
<a name="API_RecordActivityTaskHeartbeat_RequestParameters"></a>

For information about the parameters that are common to all actions, see [Common Parameters](CommonParameters.md).

The request accepts the following data in JSON format.

 ** [details](#API_RecordActivityTaskHeartbeat_RequestSyntax) **   <a name="SWF-RecordActivityTaskHeartbeat-request-details"></a>
If specified, contains details about the progress of the task.
Type: String
Length Constraints: Maximum length of 2048.
Required: No

 ** [taskToken](#API_RecordActivityTaskHeartbeat_RequestSyntax) **   <a name="SWF-RecordActivityTaskHeartbeat-request-taskToken"></a>
The `taskToken` of the [ActivityTask](API_ActivityTask.md).
 `taskToken` is generated by the service and should be treated as an opaque value. If the task is passed to another process, its `taskToken` must also be passed. This enables it to provide its progress and respond with results.
Type: String
Length Constraints: Minimum length of 1. Maximum length of 1024.
Required: Yes

## Response Syntax
<a name="API_RecordActivityTaskHeartbeat_ResponseSyntax"></a>

```
{
   "cancelRequested": boolean
}
```

<a name="API_RecordActivityTaskHeartbeat_ResponseElements"></a>

Set to `true` if cancellation of the task is requested.
Type: Boolean
