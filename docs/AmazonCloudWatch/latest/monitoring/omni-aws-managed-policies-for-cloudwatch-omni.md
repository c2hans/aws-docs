# AWS managed policies for CloudWatch Omni

CloudWatch Omni provides AWS managed policies for the space operator role, for the domain access role of an organization domain, for the roles that support organization-level Context Graph enablement, and for the role that your organization's administrator uses to set up a space in a member account. Each policy's details — the description, what it attaches to, the version history, and the complete JSON policy document — are published in the [AWS Managed Policy Reference](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/policy-list.html), which is generated from the policy itself and updated automatically when a policy changes. The following table links to each policy's page there.

For guidance on which policy you need for which task, which permissions read across your whole account, and the permissions you provide yourself, see [IAM policies to use CloudWatch Omni](omni-iam-policies-to-use-cloudwatch-omni.md).

## The policies
<a name="omni-aws-managed-policies-for-cloudwatch-omni-the-policies"></a>

| Policy | What it grants |
| --- | --- |
| [CloudWatchOmniSpaceAccessPolicy](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/CloudWatchOmniSpaceAccessPolicy.html) | The base policy, always attached to the space operator role. The space experience (space and access-grant management, telemetry queries, the context graph, alerts, service level objectives (SLOs), dashboards, access profiles, views, lookups, threads, experiments, and integrations), together with the management side of evaluation. |
| [CloudWatchOmniModelInferencePolicy](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/CloudWatchOmniModelInferencePolicy.html) | Model inference only. Attached only to spaces that use the prompt playground or run evaluations that invoke a model. |
| [CloudWatchOmniDomainAccessPolicy](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/CloudWatchOmniDomainAccessPolicy.html) | Domain management for an organization domain. Attached to the domain access role, which CloudWatch Omni assumes to operate the domain. The role is created in the management account during organization domain setup. Single-account domains do not use it. |
| [CloudWatchOmniAWSIntegrationPolicy](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/CloudWatchOmniAWSIntegrationPolicy.html) | Resource discovery for Context Graph: lets CloudWatch Omni discover resources and their relationships in an account. Optional on the space operator role — you choose it during space setup. In an organization Centralization rule, CloudWatch Omni also attaches it to the integration roles it provisions in each source account. On the space operator role, replace it with CloudWatchOmniAWSIntegrationPolicyV2, as the following note describes. |
| [CloudWatchOmniAWSIntegrationPolicyV2](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/CloudWatchOmniAWSIntegrationPolicyV2.html) | Everything in CloudWatchOmniAWSIntegrationPolicy, plus read access to the logs, traces, and profiles in your account's default CloudWatch Dataset. See [Permissions in CloudWatchOmniAWSIntegrationPolicyV2](omni-iam-policies-to-use-cloudwatch-omni.md#omni-iam-policies-to-use-cloudwatch-omni-permissions-in-cloudwatchomniawsintegrationpolicyv2). In an organization Centralization rule, CloudWatch Omni attaches CloudWatchOmniAWSIntegrationPolicy, not this policy, to the integration roles in source accounts. |
| [CloudWatchOmniDevOpsAgentInvestigationServiceRolePolicy](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/CloudWatchOmniDevOpsAgentInvestigationServiceRolePolicy.html) | With this policy, you can have CloudWatch Omni run AWS DevOps Agent investigations for you. It can create and update tasks, read their progress and findings, and discover the topology of an agent space. It covers only agent spaces in your own account. CloudWatch Omni attaches it to the role that it creates when you connect the AWS DevOps Agent integration. |
| [AWSCloudWatchOmniServiceRolePolicy](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/AWSCloudWatchOmniServiceRolePolicy.html) | Attached to the AWSServiceRoleForCloudWatch\_Omni service-linked role. In member accounts, the role provisions the integration roles, the AWS Config recorder, and the roles that your organization's administrator uses to set up a space. You cannot attach this policy to your own identities. |
| [CloudWatchOmniProvisioningPolicy](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/CloudWatchOmniProvisioningPolicy.html) | Setting up CloudWatch Omni in a member account on behalf of your organization's administrator. With this policy, the administrator can create, read, and delete the account's space and its Dataset integration, and pass the roles that they use. CloudWatch Omni attaches it to the CloudWatchOmniProvisioningRole role, which the AWSServiceRoleForCloudWatch\_Omni service-linked role creates in the member account. See [Permissions in CloudWatchOmniProvisioningPolicy](omni-iam-policies-to-use-cloudwatch-omni.md#omni-iam-policies-to-use-cloudwatch-omni-permissions-in-cloudwatchomniprovisioningpolicy). |

**Important**
If your space operator role has `CloudWatchOmniAWSIntegrationPolicy`, replace it with `CloudWatchOmniAWSIntegrationPolicyV2`. `CloudWatchOmniAWSIntegrationPolicy` does not let CloudWatch Omni read the logs, traces, and profiles in your account's `default` CloudWatch Dataset. `CloudWatchOmniAWSIntegrationPolicyV2` includes every permission in `CloudWatchOmniAWSIntegrationPolicy`, so the role does not need both. The permissions that `CloudWatchOmniAWSIntegrationPolicyV2` adds read the content of the `default` Dataset in every Region of your account, and access grants do not limit them.
To replace the policy, attach `CloudWatchOmniAWSIntegrationPolicyV2` to the role in IAM, and then detach `CloudWatchOmniAWSIntegrationPolicy`. Attach the new policy first so that resource discovery keeps working while you make the change. If your `default` Dataset is encrypted with a customer managed key, the key policy must also allow `kms:Decrypt` for the role. See [Sample key policy](omni-data-encryption-in-cloudwatch-omni.md#omni-data-encryption-in-cloudwatch-omni-sample-key-policy). For the permissions that `CloudWatchOmniAWSIntegrationPolicyV2` adds, see [Permissions in CloudWatchOmniAWSIntegrationPolicyV2](omni-iam-policies-to-use-cloudwatch-omni.md#omni-iam-policies-to-use-cloudwatch-omni-permissions-in-cloudwatchomniawsintegrationpolicyv2).
