# Release notes for AWS Support

This section describes the new features, improvements, and bug fixes for the AWS Support Center Console, the AWS Support App in Slack, and the AWS Support contact and abuse forms, organized by release month.

## October 2026
<a name="support-release-notes-october-2026"></a>

The following table lists the October 2026 releases.

| Release type | Release notes |
| --- | --- |
| New features |  +  **Unified case details is available on all support plans.** Customers on Basic, Developer, Business, AWS Business Support\+, Enterprise Support, and Unified Operations plans can switch to the unified case details view, which brings the case, its correspondence, and related AI-enhanced troubleshooting conversations into one page. Customers who prefer the classic view can switch back at any time from the **Prefer the classic experience?** banner, and their choice is remembered. <br />+  **Case links open in unified case details for customers who use it.** Links to a case from the **Active cases** list, the case history table, older `/support/cases` links, email notifications, and bookmarks now open the case in unified case details when the customer uses that experience. Previously these links opened the classic view, which left customers with no way back to the view they had chosen. <br />+  **The Support Center home page shows open cases in **Pick up where you left off** for unified case details customers.** For customers using unified case details, open cases now appear as cards in the **Pick up where you left off** section of the dashboard, and the separate **Active cases** list is no longer shown to avoid listing the same cases twice. Customers using the classic experience still see **Active cases**. The **Active cases** list also now updates immediately when a case is resolved or reopened from the case header, instead of only after a page reload. <br />+  **While You Wait: get help from AI-enhanced troubleshooting while your case is created.** While You Wait offers eligible customers an AI-enhanced troubleshooting conversation during case creation. If the conversation does not resolve the issue, the customer continues to a case with the description already filled in from the conversation, and the case stays linked to that conversation. <br />+  **Customers can send feedback on the new case experience from the switch banner.** The questions on the unified case details switch banner now open a short feedback form, so customers can tell us how the new experience is working without leaving the case. <br />+  **Case email notifications are delivered in the customer's chosen language.** For cases opened in Spanish, Portuguese, French, Chinese, Japanese, or Korean, the body of case email notifications is now automatically translated into the customer's selected language before they are sent, including when the case is handled by an engineer working in a different language. No customer action is required, and the original English text remains available in the Support Center. <br />+  **Abuse reports accept up to 10 URLs for web content, email, and child sexual abuse material reports.** Reporters can enter up to 10 space-separated URLs in a single web content, email, or child sexual abuse material (CSAM) abuse report, and each URL is now submitted as its own incident. Previously, any report with more than one URL in these categories was rejected with a validation error, even though the field accepted multiple URLs. A hint under the field now explains how to separate multiple URLs. In the China Regions, reports in these categories are still limited to one URL each.   |
| Improvements |  +  **Live chat status checks are more efficient.** The Support Center now checks live chat status more efficiently, and browser tabs running in the background no longer poll for chat status. Chat checks run only while the page is visible or the chat window in that tab is open, which reduces delays for customers who are actively chatting. <br />+  **The report abuse form shows a clearer message when the service has a problem.** If an abuse report cannot be submitted because of a server-side error, the form now shows **Something went wrong** instead of a message suggesting that the reporter entered invalid information. Validation messages are still shown when a field needs to be corrected. <br />+  **The abuse forms validate IP addresses and non-English names consistently with the processing service.** The abuse forms now reject, at the field, IPv6 addresses written with an embedded IPv4 address or a zone ID, and names that contain an ideographic (full-width) space. These inputs previously passed the form and were rejected after submission, such as Japanese company names that contain a full-width space.   |
| Bug fixes |  +  **A Cancel live chat action appears when an earlier chat blocks a new chat request.** If a customer requests a new chat while an earlier chat session is still open, the Support Center now shows a **Cancel live chat** action so the customer can end the earlier session and continue. The action appears only after a fresh check confirms the earlier chat is still waiting or active. <br />+  **The "Support agent assigned" notice appears in the correct position.** The notice that a support agent has been assigned now appears in the correct place in the conversation, before the agent's first reply instead of after it. <br />+  **Additional contacts with invalid domain names are rejected at the field.** In the classic create case form, additional contact addresses whose domain contains a label that starts or ends with a hyphen (for example, `name@example-.com`) now show an inline invalid-email error. Previously the form accepted them and the request failed when the case was submitted. <br />+  **The unified case details view shows only AI-enhanced troubleshooting conversations that belong to the signed-in user.** When a case lists a related AI-enhanced troubleshooting conversation, the unified case details view now shows it only if it belongs to the person viewing the case. Previously, some closed conversations that were not linked to the case could be displayed. <br />+  **Unanswered follow-up questions in AI-enhanced troubleshooting are kept when a conversation is reopened.** When a customer reopens an AI-enhanced troubleshooting conversation from a case, a follow-up question that had not been answered now keeps its answer form, and a message the customer just sent is no longer replaced by an empty response until the page is refreshed.   |

## September 2026
<a name="support-release-notes-september-2026"></a>

The following table lists the September 2026 releases.

| Release type | Release notes |
| --- | --- |
| New features |  +  **Basic Support customers can now add CC email addresses to support cases.** Customers on the Basic Support plan can add CC email addresses to their support cases so colleagues receive case correspondence. Previously, the CC email option was unavailable to Basic Support customers. <br />+  **The Support Center tells customers on IPv6-only networks which features are unavailable, instead of showing no message.** The Support Center now detects when a customer is connected from an IPv6-only network. The AWS Trusted Advisor widget on the Support Center home page shows an "unavailable" message rather than a request that doesn't complete. In create case, the live chat contact option is disabled on IPv6-only networks and a notice directs the customer to the web or phone contact options, or to reconnect from a dual-stack network. Phone callback is not affected. In AWS GovCloud (US), where the Support Center APIs remain IPv4-only, customers on an IPv6-only network see a site-wide banner explaining that the Support Center is unavailable over that connection. <br />+  **Contact and abuse forms can display service status banners during degraded operations.** The authenticated reverse DNS, simulated events, and abuse report forms, and the unauthenticated One Support contact site, can now show a warning banner when a backend service that processes these forms is degraded. <br />+  **AI-enhanced troubleshooting responses can show progress as a step-by-step tree.** When AI-enhanced troubleshooting works through a multi-step request in the Support Center, its progress can now appear as an expandable tree of categories, tasks, and details, each with its own status, instead of a flat list. The step that is currently running expands automatically.   |
| Improvements |  +  **The AWS Support App in Slack console page works on the dual-stack console domain.** The AWS Support App in Slack configuration page in the Support Center Console now connects to the AWS Support App endpoint that matches the console domain the customer is using, including the dual-stack (IPv4 and IPv6) domain. <br />+  **Report abuse and other AWS Trust & Safety forms validate email addresses and tracking IDs before submission.** The report abuse, Digital Millennium Copyright Act (DMCA), reverse DNS, and simulated events forms now apply the same email address rules as the service that processes them. Addresses with an invalid domain (for example, a domain that starts with a symbol) or with more than 64 characters before the "@" are rejected at the field with an inline error, instead of failing after submission with a generic backend error. The optional tracking ID on the abuse form is now limited to 50 characters.   |
| Bug fixes |  +  **AWS Support App in Slack returns a clear authorization error while a Slack workspace is migrating into an Enterprise Grid organization.** When a Slack workspace connected to the AWS Support App is being moved into a Slack Enterprise Grid organization, Slack temporarily requires an organization login. The AWS Support App now reports this as an authorization error rather than an internal service error, so customers and their administrators can see that the fix is on the Slack side.   |
