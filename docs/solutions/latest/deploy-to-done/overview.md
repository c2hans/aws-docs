# Overview
<a name="overview"></a>

**Who should read this journey:** Full-Stack Leads, Technical Founders/CTOs, .NET/Java Application Owners, Backend Engineers in organizations where application delivery outpaces operational capacity.

Every application your team ships adds operational weight: deployments to orchestrate, patches to apply, scaling to tune, health to monitor. In organizations where application delivery outpaces operational capacity, that weight compounds until infrastructure management consumes more engineering time than product development. The applications keep growing. The operational capacity does not.

AWS Elastic Beanstalk is a managed application platform where you provide the application and AWS takes permanent operational responsibility for the environment that runs it. Deploying, scaling, patching, monitoring, upgrading: continuously, for the life of the application. This journey starts with a hands-on deployment, then explains why operational ownership transfer matters, helps you evaluate whether Elastic Beanstalk fits your workloads and where it sits in the broader AWS portfolio, and gives you practical paths for migration, cost modeling, and CI/CD integration.

Whether you are migrating from a platform that has shifted its development focus, moving established .NET and Java applications off on-premises servers, or replacing hand-managed deployments on self-managed EC2 instances, this journey gives you a structured path to managed application operations.

## How This Journey Works
<a name="how-this-journey-works"></a>

This journey is structured so you experience the platform first, then decide whether it fits, then expand usage across your organization. You start by deploying a sample application (Quickstart), then evaluate the operational model and workload fit, then migrate existing applications, understand cost dynamics, and integrate deployment into your engineering workflows. Each section is self-contained. Enter at the section that matches where you are today.
