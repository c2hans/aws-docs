# ADVPERF03-BP04 Use single-zone high-performance object storage for latency-sensitive ad serving and model artifact retrieval
<a name="advperf03-bp04"></a>

 Use high-performance single-zone object storage when your advertising workloads need single-digit-millisecond data access. This storage keeps data within a single zone and delivers lower latency than standard multi-zone storage for read and write operations. It fits bid evaluation engines that load model artifacts, dynamic creative optimization services retrieving assets, and audience processing pipelines that consume intermediate data with tight latency requirements.

 **Desired outcome:**
+  Latency-sensitive advertising workloads retrieve data from storage in single-digit milliseconds.
+  Directory buckets are colocated in the same Availability Zone as your compute, removing cross-AZ network hops from the critical path entirely.
+  Session-based authentication reduces per-request authentication overhead for high-frequency model artifact retrievals.
+  Authoritative data (raw event logs, primary audience records) remains in Amazon S3 Standard for multi-AZ durability, while ephemeral data (cached artifacts, intermediate results) uses Express One Zone.

 **Common anti-patterns:**
+  Storing latency-sensitive model artifacts in S3 Standard when your compute retrieves them from a different Availability Zone, so cross-AZ hops push p99 GET latency from single-digit to tens of milliseconds.
+  Using S3 Express One Zone for authoritative data (raw event logs, primary campaign records) where multi-AZ durability is required.
+  Accessing S3 Express One Zone directory buckets from a different Availability Zone than where the bucket was created, which reintroduces the cross-AZ traversal that Express One Zone is designed to avoid.

 **Benefits of establishing this best practice:**
+  S3 Express One Zone delivers up to 10x lower latency than S3 Standard for GET and PUT operations, with support for up to 2 million read requests and 200,000 write requests per second per directory bucket.
+  For bid evaluation engines that load model artifacts on every request cycle, keeping per-request storage access latency in the single-digit-millisecond range preserves the latency budget available for the rest of the bid processing logic.
+  Session-based authentication removes per-request signing overhead, reducing authentication latency at high request rates.

 **Level of risk exposed if this best practice is not established:** High

## Implementation guidance
<a name="implementation-guidance"></a>

 Standard Amazon S3 GET requests from compute in a different Availability Zone traverse the cross-AZ network path. P99 GET latency for S3 Standard typically reaches tens of milliseconds when accessed cross-AZ, compared to single-digit milliseconds for S3 Express One Zone directory buckets colocated in the same Availability Zone as compute. For bid evaluation engines that load model artifacts on every request cycle, this per-request latency difference accumulates across concurrent retrievals and can push data access latency beyond the budget available within the 100 ms real-time bidding window.

 Use S3 Express One Zone for data that meets three criteria: it is accessed frequently on the critical path, it can be regenerated if lost (since Express One Zone stores data in a single Availability Zone), and it is consumed by compute in a known Availability Zone.

 The primary advertising use cases are:
+  **ML model artifact retrieval:** Model weights and feature tables loaded by bid evaluation engines during each request cycle. These artifacts are generated by training pipelines and cached in Express One Zone for fast retrieval during auction processing.
+  **Ad creative asset serving:** Image components and video segments consumed by dynamic creative optimization services. Creative assets are generated or validated by creative quality pipelines and served from Express One Zone to minimize ad response latency.
+  **Intermediate audience processing data:** User profile fragments and segment membership lists generated by upstream processing steps that downstream services consume within seconds. These intermediate objects exist transiently in the pipeline and can be regenerated from source data if lost.

 S3 Express One Zone uses session-based authentication that establishes a bucket-specific session and reuses session credentials for subsequent calls, removing the per-request signing overhead. For bid evaluation engines making frequent, high-concurrency artifact retrievals, this reduction in per-request overhead contributes to throughput under load.

 Express One Zone achieves this latency by storing data in a single Availability Zone, which reduces durability. Authoritative advertising data (raw bid logs, primary audience records, and campaign source files) must remain in S3 Standard for 11-nine durability. Use S3 Express One Zone as a high-performance cache layer backed by S3 Standard as the authoritative store.

### Implementation steps
<a name="implementation-steps"></a>

1.  **Identify advertising data appropriate for S3 Express One Zone:** Audit your bid evaluation pipeline to identify data accessed on the critical path that can be regenerated if lost. Typical candidates: compiled ML model files loaded by bid evaluators, pre-processed feature tables used for real-time audience enrichment, cached VAST response templates, and temporary creative composition assets. Exclude authoritative data (raw bid logs, primary audience records) from Express One Zone.

1.  **Create directory buckets colocated with your compute Availability Zone:** When creating an S3 Express One Zone directory bucket, select the same Availability Zone as your EC2 instances, ECS tasks, or EKS pods that will access it. Use the Availability Zone ID (for example, use1-az4) rather than the Availability Zone name (for example, us-east-1d) when specifying the bucket location for consistent Availability Zone mapping across AWS accounts. A directory bucket accessed from a different Availability Zone reintroduces the cross-AZ network traversal that Express One Zone is designed to avoid.

1.  **Implement session-based authentication:** Use the CreateSession API to establish a bucket-specific session and cache the returned session credentials for subsequent requests to the same bucket. Refresh the session before it expires (session credentials are valid for 5 minutes). This removes the per-request SigV4 signing overhead, which is significant at the request rates seen during bid evaluation under load.

1.  **Benchmark latency improvement before migrating production workloads:** Measure p50 and p99 GET latency for your specific access patterns on both S3 Express One Zone and S3 Standard in your Availability Zone. Confirm that the latency improvement keeps storage access latency within your bid response time budget. The realized improvement depends on object size, request concurrency, and colocation configuration. Benchmark with your actual access patterns rather than relying solely on published specifications.

1.  **Implement a write-through cache pattern:** Write model artifacts and creative assets to S3 Standard as the authoritative store and simultaneously to S3 Express One Zone as the serving cache. Configure lifecycle rules on Express One Zone buckets to expire cached objects after a TTL appropriate to your update frequency. This means the authoritative copy remains available for regeneration if the Express One Zone copy is lost.
