# Next steps
<a name="next-steps"></a>

We recommend adopting Amazon RDS Proxy to increase your application scalability, performance, and availability. For help with determining which of your databases will benefit most from adopting an RDS Proxy endpoint, see [Planning where to use RDS Proxy](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/rds-proxy-planning.html).

In addition, explore other solutions, such as [sharding](https://aws.amazon.com/blogs/database/sharding-with-amazon-relational-database-service/), [partitioning](https://aws.amazon.com/blogs/database/improve-performance-and-manageability-of-large-postgresql-tables-by-migrating-to-partitioned-tables-on-amazon-aurora-and-amazon-rds/), and [autovacuum](https://aws.amazon.com/blogs/database/understanding-autovacuum-in-amazon-rds-for-postgresql-environments/) improvements on the PostgreSQL database.

For help with assessment and the architecture improvements described in this guide, you can contact [AWS Professional Services](https://aws.amazon.com/professional-services/).
