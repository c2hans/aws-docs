## SigV2 still live
- "any new regions after January 30, 2014 will support only Signature Version 4" → SigV2 (HMAC-SHA1) STILL ACCEPTED in all pre-2014 regions (us-east-1, us-west-1, us-west-2, eu-west-1, ap-southeast-1/2, ap-northeast-1, sa-east-1). Weak MAC, legacy path.

## SigV2 StringToSign coverage gaps (Lens Y)
- StringToSign = Verb\nContent-MD5\nContent-Type\nDate\nCanonicalizedAmzHeaders\nCanonicalizedResource
- Body NOT bound unless Content-MD5 present ("Content-MD5 is left blank in the StringToSign, because it is not present in the request"). Optional → body-substitution on a signed/presigned request without breaking sig.
- Only Content-MD5 + Content-Type entity headers signed: "only the Content-Type and Content-MD5 HTTP entity headers appear in the StringToSign. The other Content-* entity headers do not." → Content-Disposition/Content-Encoding/Content-Length unsigned → MITM/tamper.
- Only x-amz-* request headers signed; all other non-positional headers unsigned (Range, If-Match, etc.).
- Query-string params NOT in CanonicalizedResource unless in fixed subresource allowlist: "Query string parameters might also appear in the Request-URI but are not included in CanonicalizedResource."
- Fixed subresource allowlist: acl, lifecycle, location, logging, notification, partNumber, policy, requestPayment, uploadId, uploads, versionId, versioning, versions, website + response-* override params + delete. OMITS all modern subresources (?tagging ?encryption ?replication ?object-lock ?retention ?legal-hold ?select ?intelligent-tiering ?analytics ?inventory ?metrics ?accelerate ?publicAccessBlock ?ownershipControls ?cors). Under SigV2 these subresource ops are UNSIGNED → request-tamper to add/alter them.

## Presigned / query-string auth (Lens Y / M)
- Expires = absolute epoch seconds, no documented upper bound → arbitrarily far-future, essentially permanent presigned URLs.
- "The validation constraint on request date applies ONLY to authenticated requests that do NOT use query string authentication." → presigned URLs have NO 15-min skew/replay window; replayable until Expires.
- Whole auth is in the URL → leaks via logs/referer/history. Survives key/role revocation until Expires (classic).

## Header-auth replay window
- 15-min clock-skew tolerance (RequestTimeTooSkewed). Over http:// an intercepted header-authed request is replayable for 15 min.

## Virtual-hosted vs path-style canonicalization (Lens BB)
- CanonicalizedResource identical for both forms after path append. Bucket pulled from Host header (virtual-hosted) or path (path-style).
- CNAME host becomes signed resource: example "Host: static.example.com:8080" → CanonicalizedResource "/static.example.com/db-backup.dat.gz". The Host header literally determines the signed bucket path → front proxy/CDN Host rewrite = divergence candidate.

## Cleartext
- http:// tolerated ("For stronger protection against eavesdropping, use the HTTPS transport"). IPv6 test example uses http://. No aws:SecureTransport mention here.

## IPv6 / dual-stack SourceIp bypass (Lens Y/S/U)
- ipv6-access.md VERBATIM: "IP address filtering policies that are not updated to handle IPv6 addresses may result in clients incorrectly losing or gaining access to the bucket when they start using IPv6." and "Avoid using IP address filtering in bucket policies."
- Dual-stack endpoint: {bucket}.s3.dualstack.{region}.amazonaws.com — reachable by same creds; an IPv4-only aws:SourceIp Allow fails to constrain an IPv6 client → request from an unlisted IPv6 range is OUTSIDE the Deny/Allow range.
